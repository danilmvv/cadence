# Cadence — дизайн

Дата: 2026-09-17
Статус: утверждён в брейншторме, готов к написанию плана реализации

## 1. Что это и зачем

Cadence — личный iOS-тулкит переиспользуемых анимаций, микроинтеракций и хаптиков
для пет-проектов. Ключевое отличие от «папки с красивыми эффектами»: набор эффектов,
их длительности и правила применения выведены из исследований восприятия и
интерфейсных гайдлайнов, а сами правила зашиты в типы и проверяются тестами.

### Цели

1. Подключить тулкит в новый пет-проект одной строкой и получить консистентный
   язык обратной связи — движение плюс тактильность — без повторного проектирования.
2. Дать проверяемый ответ на вопрос «почему именно такая анимация и именно здесь».
3. Сделать злоупотребление эффектами трудным: чем реже эффект уместен,
   тем больше усилий требуется, чтобы его применить.

### Не-цели

- Не игровой движок и не замена SpriteKit. Никаких физических симуляций,
  систем частиц общего назначения, таймлайнов.
- Не дизайн-система. Ни цветов, ни типографики, ни компонентов. Только поведение.
- Не кроссплатформенность. Только iOS 26+, только SwiftUI.
- Не библиотека для публикации в открытый доступ в v1. Если захочется — потом,
  это не влияет на архитектуру.

## 3. Метод: как ресерч связан с кодом

Каждое утверждение в ресерч-корпусе получает грейд силы доказательства:

| Грейд | Что это |
|---|---|
| A | Фундаментальные пороги восприятия, воспроизведённые десятилетиями |
| B | Вендорские гайдлайны с внятным обоснованием (Apple HIG, NN/g, Material) |
| C | Единичные исследования или отраслевая практика с измерениями |
| D | Фольклор: повторяется всюду, первоисточника нет |

**Правило приёмки.** Эффект уровня `workhorse` не принимается в тулкит на
доказательстве слабее B. Эффектам уровня `signature` разрешено стоять на C и D,
но в документации к такому эффекту прямым текстом указано, что основание —
эстетическое, а не эмпирическое.

Связь двусторонняя: DocC каждого публичного эффекта ссылается на файл ресерча,
раздел ресерча ссылается на символ API.


Граф зависимостей — дерево, без циклов:

```
CadenceCore  ←  CadenceHaptics  ←┐
     ↑                            ├─  Cadence
     └────────  CadenceMotion   ←┘
```

**Почему разделено.** Во-первых, `CadenceHaptics` подключается в проект отдельно,
когда нужен только тактильный язык. Во-вторых, граница запрещает `CadenceMotion`
дёргать хаптик напрямую: связка движения и тактильности собирается только
в семантическом слое, поэтому они не могут разъехаться по времени и смыслу.
`CadenceCore` не знает ни о движении, ни о хаптиках.

### Известная засада: шейдеры в SPM

Metal-файлы в SPM компилируются в бандл модуля, а не в дефолтную библиотеку.
Обращение только через `ShaderLibrary.bundle(.module)`. Если это нарушить,
эффект работает в каталоге и молча превращается в no-op в чужом проекте.
Закрывается тестом, который грузит шейдер через бандл модуля.

## 5. Словарь (CadenceCore)

```swift
// Ось 1 — частота. Определяет, насколько трудно применить эффект.
public enum Tier: Sendable {
    case workhorse   // сотни раз за сессию
    case accent      // единицы раз за сессию
    case signature   // раз в сессию и реже, только по явному опт-ину
}

// Ось 2 — характер изменения. Определяет бюджет длительности.
public enum ChangeClass: Sendable {
    case direct      // прямое манипулирование объектом   → immediate
    case screen      // заметное изменение на экране      → transition
    case journey     // крупное перемещение               → journey
    case persistent  // длящееся состояние, не переход    → бюджет неприменим
}

public enum MotionBudget {
    public static let immediate: Duration  = .milliseconds(100)  // порог Нильсена 0.1 с  [A]
    public static let transition: Duration = .milliseconds(300)  // NN/g 200–300 мс       [B]
    public static let journey: Duration    = .milliseconds(400)  // NN/g верхняя граница  [B]

    public static func limit(for change: ChangeClass) -> Duration? {
        switch change {
        case .direct:     immediate
        case .screen:     transition
        case .journey:    journey
        case .persistent: nil        // скелетон живёт, пока идёт загрузка
        }
    }
}

public struct CadenceContext: Sendable, Equatable {
    public var reduceMotion: Bool
    public var reduceTransparency: Bool
    public var lowPower: Bool
    public var hapticsAvailable: Bool
    public var sceneActive: Bool
}

public struct MotionSpec: Sendable, Equatable {
    public var duration: Duration
    public var curve: Curve              // .easeOut | .easeIn | .easeInOut | .spring(...)
    public var change: ChangeClass       // задаёт применимый бюджет
    public var kind: MotionKind          // декларативное описание, не реализация
}

public struct HapticSpec: Sendable, Equatable {
    public var pattern: HapticPattern
    public var minimumInterval: Duration   // троттлинг
}

public struct FeedbackPlan: Sendable, Equatable {
    public var motion: MotionSpec?
    public var haptic: HapticSpec?
    public var tier: Tier
}

public protocol MotionEffect {
    var tier: Tier { get }
    var budget: Duration { get }
    var reducedAlternative: MotionSpec { get }   // не может быть «ничего»
}
```

**Две оси ортогональны, и это важно.** Частота отвечает на вопрос «как часто это
уместно» и управляет строгостью опт-ина. Характер изменения отвечает на вопрос
«сколько это должно длиться» и управляет бюджетом. Их склейка — ошибка:
`contentArrival` срабатывает постоянно, то есть `workhorse`, но по характеру это
изменение экрана, и 100 мс для него слишком резко. А скелетон загрузки вообще
не переход: он длится ровно столько, сколько идёт работа, и бюджет к нему
неприменим.

`MotionSpec` описывает движение декларативно и не содержит вью. Благодаря этому
резолвер остаётся чистой функцией без UIKit и SwiftUI, а значит тестируемым.

## 6. Слой примитивов: восемь эффектов v1

### Workhorse — видно постоянно

**`pressResponse`** (`.direct`, ≤100 мс) — отклик на нажатие. Уменьшение до 0.96 с пружиной.
Хаптик: лёгкий импакт. Основание: порог мгновенности 0.1 с [A]; ниже этого порога
отклик неотличим от прямого манипулирования объектом.
Когда не нужен: на элементах, которые и так меняют экран мгновенно.

**`selectionShift`** (`.direct`, ≤100 мс) — смена выбранного элемента: сегменты,
табы, пикеры. Перемещение индикатора по дуге. Хаптик: selection, обязательный
троттлинг. Основание: [B] NN/g про дуговые траектории, [B] Apple HIG про
консистентность системных хаптиков.
Когда не нужен: если выбор не меняет видимого состояния.

**`contentArrival`** (`.screen`, ≤300 мс) — появление контента. Ease-out, каскад для списков.
Каскад ограничен по числу элементов: задержка последнего элемента не может
превысить `MotionBudget.journey`, дальше элементы появляются одновременно.
Основание: [B] ease-out для входа, асимметрия входа и выхода.
Когда не нужен: при возврате на уже виденный экран — повторная анимация
появления читается как перезагрузка.

### Accent — видно единицы раз за сессию

**`waitingState`** (`.persistent`, бюджет неприменим) — состояние ожидания.
Единственный эффект, который прямо запрещает часть поведения:

| Ожидание | Поведение |
|---|---|
| < 1 с | не показывать ничего |
| 1–10 с | скелетон или шиммер |
| > 10 с | детерминированный прогресс с возможностью отмены |

Основание: три порога отклика [A]. Индикатор, живущий 300 мс, воспринимается
как мерцание и делает интерфейс субъективно медленнее. Предпочтение скелетона
спиннеру на содержательных экранах — [C].

**`validationFailure`** (`.screen`, 300 мс) — ошибка ввода. Затухающее
горизонтальное потряхивание, хаптик error. Основание: [B] Apple HIG про обратную связь на неуспех.

**`taskSuccess`** (`.screen`, 250 мс) — подтверждение завершения. Прорисовка
галочки, хаптик success. Основание: [B] HIG, [C] исследования про подтверждающую
обратную связь.

### Signature — только по явному опт-ину

**`disintegrate`** (`.journey`, ~900 мс — превышение бюджета осознанное) — щелчок Таноса. `layerEffect` с Metal-шейдером: выходной пиксель
сэмплирует слой со смещением, заданным шумом и прогрессом, альфа гасится по
порогу шума; `maxSampleOffset` задаёт запас кадра под разлёт. ~900 мс, плюс
CoreHaptics-паттерн с затухающей continuous-фазой.
Превышение `journey` — плата за весомость; ровно поэтому эффект заперт за опт-ином.
Уместно: необратимое удаление, где важно, чтобы действие ощущалось весомым.
Неуместно: любое обратимое действие, любой массовый список.
Основание: [D]. Эстетическое решение, эмпирической базы нет — так и записано.

**`cornerEmergence`** (`.journey`, ~450 мс — превышение бюджета осознанное) — выход
элемента из угла экрана. Реальный радиус угла
устройства берётся через `concentricCornerRadii(in:)` в `onGeometryChange`,
форма — `ConcentricRectangle`, морфинг — `GlassEffectContainer` с `glassEffectID`
в общем `@Namespace`. ~450 мс.
Уместно: статусные уведомления системного вида, индикаторы фоновых процессов.
Неуместно: основная навигация, модальные экраны с контентом.
Основание: [C] соответствие системному языку iOS 26 снижает стоимость обучения;
[D] в части самого приёма.

## 7. Семантический слой (Cadence)

### Разделение типов вместо флага

```swift
public enum RoutineInteraction: Sendable {
    case pressed
    case selectionChanged
    case contentArrived(staggerIndex: Int = 0)
    case waiting(elapsed: Duration)   // не Instant: резолвер не должен знать «сейчас»
    case validationFailed
    case taskSucceeded
}

public enum SignatureInteraction: Sendable {
    case destroyed
    case summoned(from: Edge)
}
```

Два непересекающихся типа и два разных модификатора:

```swift
button.cadence(.pressed)
row.cadenceSignature(.destroyed, trigger: isDeleted)
```

Повесить `disintegrate` на кнопку «Сохранить» нельзя не по соглашению,
а потому что не компилируется. Это основной механизм, которым ресерч
влияет на использование.

### Резолвер — чистая функция

```swift
public func resolve(_ event: RoutineInteraction,   in ctx: CadenceContext) -> FeedbackPlan
public func resolve(_ event: SignatureInteraction, in ctx: CadenceContext) -> FeedbackPlan
```

Без сайд-эффектов, без SwiftUI, без UIKit. Вся таблица соответствий
«событие → движение + хаптик + длительность + кривая» живёт здесь.

Поток данных: среда SwiftUI → `CadenceContext` → `resolve` → `FeedbackPlan` →
модификатор применяет движение и отдаёт хаптик-спеку в `HapticScheduler`.

## 8. Доступность и деградация

| Условие | Поведение |
|---|---|
| `accessibilityReduceMotion` | движение заменяется кросс-фейдом, но не исчезает |
| `accessibilityReduceTransparency` | стекло заменяется плотной заливкой |
| `isLowPowerModeEnabled` | signature деградирует до accent-альтернативы |
| нет Taptic Engine | хаптик — тихий no-op, движение сохраняется |
| сцена неактивна | хаптик не играет |

Reduce Motion не означает «выключить всё». Пользователь по-прежнему должен
понять, что состояние изменилось, поэтому `reducedAlternative` в протоколе
`MotionEffect` не может быть пустым. Основание: WCAG 2.3.3 требует возможности
отключить неосновную анимацию [B]; Apple рекомендует подменять движение
кросс-фейдом, а не удалять обратную связь [B].

Низкий заряд отдельно важен для signature: шейдер, считающийся каждый кадр, —
неподходящая нагрузка при экономии энергии.

### Хаптики: четыре вещи, которые ломаются в проде

1. Taptic Engine есть не на всех устройствах — проверка возможностей.
2. `CHHapticEngine` останавливается при уходе в фон и после системного reset;
   нужны `resetHandler` и `stoppedHandler`, иначе вибрация однажды пропадает
   до перезапуска приложения.
3. Троттлинг обязателен. `selectionChanged` на скролле без ограничения частоты
   даёт непрерывное жужжание — типовая причина, по которой хаптику отключают целиком.
   `HapticScheduler` схлопывает очередь и уважает `minimumInterval`.
4. Хаптик без визуального сопровождения запрещён: он не должен быть
   единственным носителем информации.

## 9. Обработка ошибок

Принцип: тихо в релизе, громко в разработке.

| Отказ | DEBUG | Release |
|---|---|---|
| шейдер не загрузился | `assertionFailure` с именем функции шейдера | деградация до accent-альтернативы + `OSLog` |
| `CHHapticEngine` не стартовал | лог warning | fallback на `UIFeedbackGenerator`, затем no-op |
| бюджет превышен в рантайме | `assertionFailure` | клэмп к границе tier + `OSLog` |

Голые `try?` на путях отказа запрещены. Эффект, который молча перестал работать,
заметить невозможно, потому что его отсутствие выглядит нормально.
Категории `OSLog`: `motion`, `haptics`, `resolver`.

## 10. Каталог

Отдельное iOS-приложение, ссылающееся на пакет по локальному пути.

- Экран на эффект, группировка по tier'ам.
- На каждом экране: живой эффект, ручки параметров, правило применения
  и **антипример** — тот же эффект, применённый не туда. Показанный
  `disintegrate` на кнопке «Отмена» объясняет правило лучше абзаца текста.
- Тумблеры Reduce Motion, Reduce Transparency и Low Power через переопределение
  среды — деградация проверяется не выходя в системные настройки.
- Счётчик срабатываний за сессию: делает понятие tier физически ощутимым.

Каталог — не витрина, а инструмент проверки. Хаптики и субъективное качество
движения невозможно оценить по коду.

## 11. Тестирование

**Юнит-тесты резолвера — это и есть правила ресерча:**

- для каждого плана `motion.duration <= MotionBudget.limit(for: motion.change)`,
  если предел определён; исключение допускается только при `tier == .signature`;
- ни один `.direct`-план не длиннее `MotionBudget.immediate`;
- единственные планы, превышающие `MotionBudget.journey`, — signature;
- при `reduceMotion == true` план не пуст ни для одного события;
- нет плана, содержащего хаптик при `motion == nil`;
- `waiting(elapsed:)` короче 1 с не порождает индикатор, от 1 с даёт `.persistent`-план;
- резолвер не обращается к часам: один и тот же вход даёт один и тот же выход
  в любой момент времени;
- при `hapticsAvailable == false` движение сохраняется во всех планах;
- при `lowPower == true` ни один signature-план не превышает `journey`;
- `tier` и `change` независимы: существует хотя бы один `workhorse`-эффект
  класса `.screen` (страховка от повторной склейки осей).

**Прочее:** загрузка каждого шейдера через `ShaderLibrary.bundle(.module)`;
проверка `animatableData` кастомных эффектов в промежуточных точках.

**Честное ограничение.** Хаптику автотестами проверить нельзя: ощущение вибрации
не заассертить. Тактильная часть проверяется руками на устройстве через каталог.
Это записывается в `AGENTS.md` как обязательный шаг перед признанием
хаптик-эффекта готовым, чтобы зелёные тесты не создавали иллюзию покрытия.

## 13. Принятые решения и отвергнутые варианты

**Два слоя вместо плоского каталога модификаторов.** Плоский каталог проще,
но оставляет ресерч текстом в соседнем файле: библиотека не мешает применить
эффект не туда. Двухслойная схема переводит правила в типы.

**Не «только семантика».** Полное сокрытие примитивов дисциплинирует сильнее,
но в пет-проекте нужно уметь быстро собрать новое, не расширяя библиотеку.
Примитивы остаются публичными.

**Разделение типов вместо параметра-флага.** `cadence(.destroyed, allowSignature: true)`
было бы короче, но флаг легко проставить не думая. Разные типы и разные
модификаторы требуют осознанного действия.

**Две оси, а не одна.** В первом наброске частота и длительность были одним
понятием, и `contentArrival` оказался одновременно обязан длиться не больше
100 мс (как частый эффект) и 200–300 мс (как изменение экрана). Оси разведены:
`Tier` управляет строгостью опт-ина, `ChangeClass` — бюджетом.

**Восемь эффектов, не двадцать.** Набор покрывает всю дугу частот от
постоянного к разовому. Расширение дешевле сокращения.

## 14. Что осознанно отложено

- Анимации навигационных переходов между экранами.
- Жестовые интеракции: свайпы, drag-to-dismiss, резиновые границы.
- Звуковое сопровождение. Хаптик и звук в HIG рассматриваются вместе,
  но звук требует своего ресерча и собственных правил громкости.
- Поддержка iPad и внешних дисплеев.
- Темизация и пользовательская настройка бюджетов.
